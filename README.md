# CityEye — карта здоровья города

CityEye — это карта Алматы, на которой видно, где городу плохо. Житель
фотографирует проблему на улице (яму, мусор, разбитый фонарь), нейросеть
по фото понимает, что это и насколько серьёзно, и проблема сразу ложится
на карту. Из этих точек считается «Индекс качества» по районам — чтобы и
горожане, и акимат видели одну честную картину, а не разрозненные жалобы.

Делали на хакатоне. Идея простая: замкнуть петлю между человеком, который
видит проблему, и теми, кто её решает. Без бюрократии и формы на двадцать
полей — сфотографировал, отправил, увидел на карте.

## Как это работает

**Сторона жителя.**
Открываешь карту — она и есть главный экран, как в 2ГИС. Жмёшь «Сообщить»,
выбираешь фото. Дальше работает GPT-4o Vision: определяет тип проблемы и
её серьёзность, можно поправить, если модель ошиблась. Точка появляется на
карте и попадает в индекс района. В «Моих заявках» виден статус и есть чат
с акиматом.

**Сторона акимата.**
Отдельный портал `/akimat` со своим входом — плотная рабочая консоль, а не
витрина. Очередь заявок, сортировка по важности, KPI по городу, смена
статуса в один тап и переписка с заявителем.

**Индекс качества района.**
У каждого района есть оценка 0–100: 100 — почти нет активных проблем, ниже —
больше нагрузка (с весами по серьёзности). Цвет на карте читается сразу:
зелёный — хорошо, жёлтый — средне, красный — плохо.

**Дедупликация.**
Чтобы одна яма не превратилась в десять точек, похожие заявки рядом
склеиваются: сравниваем эмбеддинги описания (косинусное сходство) и
расстояние между точками. Если совпало — новая заявка не плодит дубль, а
увеличивает счётчик «похожих».

**Границы районов** настоящие — взяли реальные полигоны Алматы из
OpenStreetMap, а не нарисовали квадраты.

## Стек

- **Бэкенд:** FastAPI, SQLAlchemy, PostgreSQL, shapely (точка-в-полигоне)
- **Фронтенд:** React + Vite, Tailwind, MapLibre GL (тайлы OpenFreeMap / CARTO)
- **ИИ:** OpenAI GPT-4o (Vision) + text-embedding-3-small.
  Без ключа всё работает в mock-режиме — на хакатоне это спасало.
- **Авторизация:** PyJWT + pbkdf2 (намеренно без тяжёлых C-зависимостей)
- **Хостинг:** Railway (backend + frontend), Supabase (БД и хранилище фото)

## Запуск локально

Нужны Python 3.10 и Node 18+.

**Бэкенд:**
```bash
cd backend
py -3.10 -m venv .venv && .venv\Scripts\activate   # Windows
pip install -r requirements.txt
python -m app.seed        # засеять 6 районов + демо-проблемы + админа
uvicorn app.main:app --reload
```
Поднимется на `http://localhost:8000`. Ключ OpenAI необязателен — без него
отработает мок. Чтобы включить настоящий ИИ: `set OPENAI_API_KEY=...`

**Фронтенд:**
```bash
cd frontend
npm install
npm run dev
```
Адрес бэкенда задаётся переменной `VITE_API_URL` (в проде указывает на
Railway-бэкенд).

## Структура

```
backend/app/
  main.py     — FastAPI, CORS, self-heal схемы и автосид на старте
  routes.py   — все эндпоинты
  model.py    — слой ИИ: Vision + эмбеддинги (с mock-фоллбэком)
  dedup.py    — склейка похожих заявок
  index.py    — расчёт индекса района
  seed.py     — демо-данные
frontend/src/
  pages/         — карта, заявка, мои заявки, профиль, вход, портал акимата
  components/ui/ — дизайн-система (кнопки, поля, бейджи, лист, иконки)
  lib/           — api, темы, авторизация, реальные границы районов
```

## Честно про пилот

Данные по районам сейчас демонстрационные — это каркас, в который
подставляются реальные обращения. Старые фото до перехода на Supabase
Storage могли потеряться. Это хакатон-MVP: цель была показать рабочую
петлю «житель → ИИ → карта → акимат», и она работает целиком.
